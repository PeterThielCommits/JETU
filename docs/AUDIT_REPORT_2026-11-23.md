## 2. Найденные и исправленные ошибки

### 2.1. Логика / i18n — английский текст в результатах мэтчинга (RU/KK)

- **Где:** `src/features/matching/localized.ts`, `src/features/matching/engine.ts`.
- **Что:** причина предпочтения «Listed annual tuition is within the stated
  budget; living costs are separate.» (фактор бюджета, вес 20) не имела
  перевода в таблице `reasons` — русско- и казахскоязычные студенты видели
  англоязычное объяснение в карточках рекомендаций.
- **Исправлено:** добавлены переводы RU/KK; регрессионный тест гарантирует,
  что **каждая** из шести причин, которые может выдать `rank()`, локализуется
  (`tests/unit/matching.test.ts`, блок «matching explanations stay localized»).

### 2.2. Дизайн / i18n — «сырые» коды перечислений БД в локализованном UI

- **Где:** `src/features/search/views.tsx` (детальные страницы стипендий и
  возможностей, карточки поиска, таблица сравнения).
- **Что:** пользователь видел внутренние коды БД вместо названий:
  `award_type` («assistantship», «bursary»), `opportunity_type`
  («summer_school»), `participation_format` («in_person»), `cost_state`
  («fee_waiver_available»), `cost_period` («academic_year») — на трёх языках.
- **Исправлено:** в `src/features/search/copy.ts` добавлены полные
  локализованные карты `awardTypes` (7 кодов), `opportunityTypes` (17 кодов),
  `periods` (7 кодов) для RU/KK/EN; создан чистый модуль меток
  `src/features/search/labels.ts` (award/opportunity/period/format/cost-state),
  подключённый к представлениям. Покрытие: `tests/unit/search-labels.test.ts`
  проверяет **каждый** код из миграций × каждую локаль + fallback на сырой код
  для будущих значений + структурное равенство карт между локалями.

### 2.3. Логика / i18n — уровень «doctorate» отображался сырым кодом и был недоступен в фильтре каталога

- **Где:** `src/features/catalog/copy.ts`, `src/features/catalog/server.ts`.
- **Что:** карта `levels` каталога не содержала `doctorate` (в отличие от
  поиска), поэтому карточки программ показывали «doctorate» как есть, а
  фильтр `/universities` не позволял выбрать докторантуру. RPC `catalog_search`
  принимает текстовый уровень — ограничение было только в UI-схеме.
- **Исправлено:** `doctorate` добавлен во все три карты `levels` (опция
  фильтра появляется автоматически) и в zod-перечисление фильтра.

### 2.4. Дизайн — «висячая» пунктуация и пустые значения в каталоге

- **Где:** `src/features/catalog/views.tsx`.
- **Что:** на странице программы строка кампуса рендерилась как «· , » при
  отсутствии данных кампуса; `study_mode` и `teaching_language` со значением
  `null` оставляли пустые места после двоеточия/точки без «неизвестно».
- **Исправлено:** блок кампуса скрывается целиком, `null`-значения формата и
  языка обучения показывают локализованное «Неизвестно / не опубликовано».

### 2.5. SEO / архитектура — robots.txt не защищал приватные маршруты

- **Где:** `src/app/robots.ts`.
- **Что:** при включённой публичной индексации (`JETU_PUBLIC_INDEXING=true`)
  в `Disallow` был только `/*/design-system`. Личные кабинетные и аккаунтные
  маршруты (`/dashboard`, `/onboarding`, `/saved`, `/match`, `/login`,
  `/signup`, `/forgot-password`, `/reset-password`, `/compare`) могли
  индексироваться поисковиками.
- **Исправлено:** все приватные/аккаунтные маршруты добавлены в `Disallow`;
  ветка без индексации (`disallow: '/'`) не изменилась. Контракт закреплён
  тестом `tests/unit/marketing-seo.test.ts`.

### 2.6. Сопутствующее — регрессионные тесты (+9)

- `tests/unit/search-labels.test.ts` — 6 тестов: полнота enum-переводов,
  fallback, структура карт по локалям.
- `tests/unit/matching.test.ts` — 2 теста: локализация всех причин ранжирования
  и всех видов/статусов правил (11 видов × 3 статуса × 2 локали).
- `tests/unit/marketing-seo.test.ts` — 1 тест: контракт robots.txt.

## 3. Проверено и признано надёжным (без правок)

Полный проход по слоям; отдельно фиксируем то, что устояло без изменений:

**Безопасность**

- XSS: `StructuredData` экранирует `<` в JSON-LD; пользовательский ввод не
  попадает в `dangerouslySetInnerHTML`; все внешние ссылки `target="_blank"`
  с `rel="noopener noreferrer"`.
- Open redirect: `safeAuthDestination` (lib/auth/redirect.ts) пускает только
  `/locale/{dashboard,onboarding,reset-password}`; `auth/callback` и
  `auth/confirm` валидируют `next` и тип OTP.
- CSRF/API: `POST /api/matching/run` требует same-origin `Origin`+`Host`,
  JSON ≤ 4 КБ, повторная проверка размера тела; `GET /api/search/suggest` —
  только allowlisted-параметры через zod.
- Ключи: publishable-ключ валидируется как anon/sb_publishable (маскировка
  service-role в `safety.ts`), admin-клиент помечен `server-only` и нигде не
  используется в user-запросах; canary-тесты бандла в CI.
- Приватность данных: owner-RLS на `student_profiles`, `matching_*`,
  `saved_*`; self-reported баллы экзаменов принудительно `verified: false`
  в `loadMatchingState`; CAS-версионирование профиля (read-check +
  compare-and-swap на записи, INSERT вместо перезаписывающего upsert).

**Логика**

- Мэтчинговый движок детерминирован: отдельные обязательные правила
  (MET/NOT_MET/UNKNOWN) и взвешенные предпочтения (сумма весов = 100),
  честная обработка неизвестного, дедлайн-проверка со свежестью источника
  (180 дней), GPA только при совпадении шкал — всё под тестами (12 тестов).
- Anti-regression: лимиты matching-запросов (20/сут, 30 сек, rate_slot),
  timeout 12s на загрузку кандидатов, границы лимитов выборок защищают от
  неполных результатов (fail closed).
- Автокомплит: WAI-ARIA combobox, отмена устаревших запросов, запрет
  переоткрытия после Escape, фокус-менеджмент — покрыто e2e.
- Прокси (`src/proxy.ts`): локаль из пути (не из заголовка), валидация
  маршрутов, refresh сессий, кэш-заголовки Supabase-адаптера сохраняются.

**Дизайн / UX / a11y**

- Полная локализация RU/KK/EN: ключи всех copy-модулей структурно совпадают
  между тремя локалями (проверено скриптом); ошибки форм переведены.
- Контраст (19 пар), axe 0 нарушений, клавиатура, reduced-motion, no-JS
  fallback анкеты, 320px-вьюпорты — подтверждено e2e и journey-набором.
- Честность данных: непроверенные записи помечаются, демо подписано, никаких
  выдуманных партнёров/исходов; неизвестные значения → «неизвестно», без оценок.

**Инженерия**

- `npm run check` платформенно-нейтрален; CI без секретов (две чистые
  реплеи миграций + pgTAP + advisors + canary); lockfile/engines/nvmrc пины;
  generated types без дрейфа.

## 7. Ограничения среды этого аудита

- **Hosted Supabase data-plane недоступен** из рабочей среды (CONNECT 403) —
  e2e выполнялся в штатном degraded-режиме (4 Auth-skip сохранены намеренно).
- **Playwright-CDN заблокирован**: использован Chromium 153 (бинарь из
  npm-пакета, NSPR собран из исходников mozilla/nspr) и шрифты Liberation
  Sans/Serif — метрики совпали с базовыми эталонами, все 6 визуальных
  сравнений прошли с нулевым диффом. Бейзлайны не перегенерировались.
- Node в среде — 22.x против закреплённого 24.19 (`engine-strict`); набор
  проверок выполнен с временным отключением engine-strict и прошёл полностью.
